# Интеграционные тесты

Тесты вызывают контроллер напрямую с настоящими сервисом, репозиторием и PostgreSQL.
Зависимости собираются так же, как в `cmd/workspace-booking-service/main.go`.
Сетевой gRPC-сервер и клиент для этих тестов не нужны. Интерсепторы и транспорт этим
набором не проверяются.

Нужен запущенный Docker. Из корня проекта:

```sh
go test -tags=integration ./internal/integration-tests/... -count=1 -v
```

Один сценарий:

```sh
go test -tags=integration ./internal/integration-tests/get-user-by-id -run 'TestGetUserByID/returns_existing_user' -count=1 -v
```

Без тега `integration` эти тесты и их инфраструктура не включаются в сборку.

## Структура

- `testdb/postgres.go` — запуск контейнера, создание отдельной базы для каждого
  теста, применение настоящих миграций и очистка через `tn.Cleanup`.
- `get-user-by-id/start_test.go` — самостоятельные сценарии с подготовкой данных,
  прямым вызовом контроллера и явными проверками ответа и состояния базы.
- `get-user-by-id/helpers_test.go` — сборка контроллера, вставка пользователя и SQL
  для чтения состояния базы независимо от кода репозитория.

Один PostgreSQL-контейнер используется всеми подтестами `TestGetUserByID`. Каждый
подтест создаёт собственную базу с миграциями, поэтому сценарии можно запускать
параллельно. После теста закрывается пул и удаляется его база; после всего набора
удаляется контейнер.

## Как добавить тест

Добавь строку в таблицу `cases`: название, начальные записи пользователей, запрос,
ожидаемый ответ и код gRPC. Общий цикл `tn.Run` создаёт отдельную базу, вставляет
данные, вызывает контроллер и проверяет ответ, код ошибки и неизменность таблицы
`users`. Порядок записей в начальных данных не влияет на проверку базы.

Новый метод с существенно другими сценариями лучше разместить в собственном
`*_test.go`. Сборку пользовательского контроллера и простые SQL-помощники можно
переиспользовать в этом пакете. Для другого домена создай отдельный пакет тестов и
используй общий `testdb`.

Небольшие запросы, ответы и фикстуры описываются типизированными Go-структурами
рядом с проверками. Объёмные данные при необходимости можно вынести в `testdata`.
YAML-конфигурации, общего `runCase` и собственного языка описания асертов нет.
